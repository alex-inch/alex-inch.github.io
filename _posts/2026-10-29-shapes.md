Anyone doing machine learning code will confirm it: one of the principle headaches in writing ML code is losing track of the _shapes_ of the things you're working with. By that I mean: does this array (or tensor, if you like Torch) have its batch or time dimension first? Are my images (Height, Width, Channels), or (Width Channels Height)? Hopefully not the latter.

# Comments

The obvious one. As used by beloved internet ML-teacher Andrej Karpathy.

```python
def call_model(model, x, y):
    # x: [A B], y: [B C]
    z = x @ y # [A C]
    return model(z)
```

Great! Now we know something about this array shape (if we open up the function and take a look).

# Variable Names
I've heard this is the trick used by Noam Shazeer (arguably the guy who made the Transformer work). Instead of relying on comments, we can bake shapes directly into the variable names we're using:

```python
def call_model(model, x_ab, y_bc):
    z_ac = x_ab @ y_bc
    return model(z_ac)
```

I like this one in principle, but I find with more complex shapes it can start to make simple things quite unreadable. Suppose I want to operate on two arrays of videos: which have a batch dimension, time dimension, and height/width/channels. And additionally, it bakes the shape information in everywhere you see a variable. Now I need to know that x is [B T H W C] literally every time it gets called? What a pain! It is unambiguous though.

```python
def add_videos(x_bthwc, y_bthwc):
  return x_bthwc + y_bthwc
```
